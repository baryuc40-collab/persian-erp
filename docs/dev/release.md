# انتشار نسخه‌ی فارسی

هر انتشار یک برچسب git به شکل `v<نسخه‌ی NocoBase>-fa.<شماره>` است، مثل `v2.2.24-fa.1`:
- نسخه‌ی NocoBase همان `NOCOBASE_VERSION` است و نشان می‌دهد پلاگین با کدام نسخه سازگار است.
- شماره با هر انتشار روی همان نسخه‌ی NocoBase یکی بالا می‌رود.
- پس از ارتقای NocoBase ([upgrade.md](upgrade.md)) شماره از ۱ شروع می‌شود.

## انتشار

push برچسب کار صاحب پروژه است، چون انتشار عمومی برگشت‌ناپذیر است.

```bash
git checkout main && git pull
git tag v<نسخه>-fa.<شماره>
git push origin v<نسخه>-fa.<شماره>
```

گردش‌کار `.github/workflows/release.yml` این کارها را انجام می‌دهد:
1. برچسب را با `NOCOBASE_VERSION` می‌سنجد. اگر نخواند، با خطای روشن متوقف می‌شود.
2. نسخه‌ی پلاگین را همان نسخه‌ی انتشار می‌کند، تا «مدیریت پلاگین‌ها» آن را نشان دهد.
3. ایمیج را با `docker/build.sh` می‌سازد و با دو برچسب `<نسخه>` و `latest` در `ghcr.io/baryuc40-collab/persian-erp` منتشر می‌کند.
4. یک GitHub Release می‌سازد. در آن فایل `plugin-fa-<نسخه>.tgz` و یادداشت انتشار فارسی هست.

یادداشت انتشار را `node tools/release notes <برچسب>` از PRهای ادغام‌شده از انتشار قبلی می‌سازد. عنوان هر PR (فارسی، با شناسه‌ی استوری) یک خط آن است. PRهایی که شناسه‌ی استوری دارند، زیر «استوری‌ها» می‌آیند.

پس از نخستین انتشار، بسته‌ی ایمیج در GitHub به‌طور پیش‌فرض خصوصی است. یک بار در Packages → persian-erp → Package settings آن را Public کنید تا `docker compose pull` بدون ورود کار کند.

## آزمایش بدون انتشار

در Actions، گردش‌کار «Release» را با «Run workflow» اجرا کنید:
- برچسب دلخواه را بدهید. لازم نیست برچسب وجود داشته باشد؛ آخرین commit شاخه ساخته می‌شود.
- `dry_run` را روشن بگذارید.

ایمیج، فایل پلاگین و یادداشت انتشار به‌صورت artifact می‌مانند و چیزی منتشر نمی‌شود.
