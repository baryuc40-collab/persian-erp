# ۰۰۰۲: قفل نسخه و سیاست ارتقای NocoBase

- **وضعیت:** پذیرفته‌شده
- **تاریخ:** ۱۹ مهر ۱۴۰۵ (۱۱ اکتبر ۲۰۲۶)
- **استوری:** [STORY-002](../../backlog/epics/EPIC-001-license-and-version/STORY-002-version-pin.md)

## زمینه

NocoBase سه کانال انتشار دارد و نسخه‌ی پایدار تقریباً هر چند روز وصله می‌گیرد:

| کانال | شاخه | نمونه در زمان تصمیم |
| --- | --- | --- |
| پایدار | `main` | v2.2.22 (۸ اکتبر ۲۰۲۶) |
| آلفا | `develop` | v2.4.0-alpha.x |
| نسل بعد | `v3-develop` | v3.0.0-alpha.x |

ترجمه‌ها به کلیدهای هر نسخه وابسته‌اند و اصلاحات RTL به CSS هسته. اگر نسخه شناور باشد، هر نصب ممکن است چیز متفاوتی ببیند.

## تصمیم

1. نسخه‌ی NocoBase **فقط** در فایل `NOCOBASE_VERSION` در ریشه‌ی مخزن تعریف می‌شود (اکنون `2.2.22`). `package.json`، Docker، CI و اسکریپت‌ها از همین فایل می‌خوانند یا با آن سنجیده می‌شوند. هیچ سند دیگری عدد نسخه را به‌عنوان منبع تکرار نمی‌کند.
2. فقط نسخه‌های کانال پایدار (`main`) پذیرفته می‌شوند؛ alpha و beta هرگز.
3. سیاست ارتقا:

| نوع ارتقا | مثال | شرط |
| --- | --- | --- |
| وصله | 2.2.22 → 2.2.30 | یک PR با: گزارش i18n (کلیدهای جدید ترجمه شده)، CI سبز، آزمون‌های تصویری RTL (وقتی وجود داشت)، مقایسه‌ی `LICENSE.txt` |
| فرعی | 2.2.x → 2.3.x | یک اپیک جدا؛ بررسی تغییرات API پلاگین و وصله‌های `patches/` |
| اصلی | 2.x → 3.x | فقط پس از انتشار پایدار 3.0 و تصمیم صریح صاحب پروژه |

4. ارتقا به وصله‌ی جدید اجباری نیست؛ وقتی انجام می‌شود که تغییری لازم داشته باشیم (رفع اشکال امنیتی یا قابلیت) یا فاصله زیاد شده باشد. STORY-003 انتشارهای جدید را گزارش می‌کند.

## پیامدها

- ارتقا یعنی تغییر یک خط در `NOCOBASE_VERSION` به‌علاوه‌ی کارهای جدول بالا، در یک PR.
- کار ما تا جای ممکن در پلاگین می‌ماند تا انتقال به 3.x ارزان باشد.
