# راهنمای سبک نگارش فارسی رابط کاربری

این راهنما برای همه‌ی مترجم‌ها (انسان و هوش مصنوعی) است. معادل اصطلاحات از [واژه‌نامه](../glossary/fa-IR.csv) گرفته می‌شود؛ این سند می‌گوید جمله‌ها را **چطور** بنویسیم.

## ۱. لحن

- رسمی و مؤدبانه، با «شما». نه خودمانی، نه اداری و پیچیده.
- کوتاه و مستقیم؛ کاربر رابط را می‌خواند تا کاری انجام دهد.

| نادرست | درست |
| --- | --- |
| آیا مطمئنی؟ | آیا مطمئن هستید؟ |
| خواهشمند است نسبت به وارد نمودن نام اقدام فرمایید | لطفاً نام را وارد کنید |

## ۲. دکمه‌ها، منوها و عنوان‌ها

- دکمه: مصدر (افزودن، بستن) یا اسم کار (ذخیره، حذف، ویرایش)؛ نه فعل امر. بدون «را»، بدون نقطه.
- عنوان و برچسب: گروه اسمی، بدون فعل.
- حروف بزرگ انگلیسی (Title Case) معادلی ندارد؛ نادیده بگیرید.

| انگلیسی | نادرست | درست |
| --- | --- | --- |
| Save | ذخیره کن | ذخیره |
| Add new | اضافه کردن یک مورد جدید | افزودن |
| Delete block | پاک کردن بلوک را | حذف بلوک |
| Configure fields | فیلدها را پیکربندی کنید | پیکربندی فیلدها |

## ۳. پیام‌ها

**موفقیت:** فعل ماضی مجهول یا «با موفقیت ... شد».

| انگلیسی | درست |
| --- | --- |
| Saved successfully | با موفقیت ذخیره شد |
| Data refreshed successfully | داده‌ها با موفقیت تازه‌سازی شدند |

**خطا:** بگویید چه شد و در صورت امکان چه باید کرد. «خطا:» در ابتدای پیام لازم نیست.

| انگلیسی | درست |
| --- | --- |
| Data loading failed | بارگذاری داده‌ها ناموفق بود |
| Code recognition failed, please scan again | تشخیص کد ناموفق بود؛ لطفاً دوباره اسکن کنید |

**پرسش تأیید:** برای کار ساده روی یک چیز، «آیا از [مصدر] [آن/شیء] مطمئن هستید؟» (مثلاً «آیا از حذف آن مطمئن هستید؟»)؛ در بقیه، «آیا مطمئن هستید که می‌خواهید ...؟» با فعل التزامی.

| انگلیسی | درست |
| --- | --- |
| Are you sure you want to delete it? | آیا از حذف آن مطمئن هستید؟ |
| Are you sure you want to perform the {{title}} action? | آیا مطمئن هستید که می‌خواهید اکشن «{{title}}» را اجرا کنید؟ |

**راهنما و placeholder:** «... را وارد کنید» یا «... را انتخاب کنید».

## ۴. متغیرها و تگ‌ها

- `{{...}}` دقیقاً همان‌طور که هست می‌ماند؛ نه ترجمه، نه فاصله‌ی اضافه درون آکولاد، نه حذف.
- ترتیب جمله را فارسی کنید؛ لازم نیست ترتیب متغیرها مانند متن انگلیسی بماند.
- متغیری که نام یا عنوان است در گیومه‌ی فارسی « » قرار می‌گیرد اگر انگلیسی آن نقل‌قول داشت.
- تگ‌های HTML (`<a>`، `<strong>`) و Markdown دست‌نخورده می‌مانند؛ فقط متن درونشان ترجمه می‌شود.

| انگلیسی | درست |
| --- | --- |
| Add {{type}} after "{{title}}" | افزودن {{type}} پس از «{{title}}» |
| Are you sure you want to load {{count}} collection(s)? | آیا مطمئن هستید که می‌خواهید {{count}} مجموعه را بارگذاری کنید؟ |

## ۵. جمع و شمارش

- پس از عدد، اسم مفرد می‌آید: «۳ رکورد»، نه «۳ رکوردها».
- `(s)` انگلیسی حذف می‌شود: `{{count}} record(s)` ← `{{count}} رکورد`.
- برای کلیدهای جمع i18next (`_one` / `_other`) هر دو صورت معمولاً یکسان‌اند.

## ۶. نگارش

- «ی» و «ک» فارسی (U+06CC، U+06A9)، هرگز «ي» و «ك» عربی.
- نیم‌فاصله (U+200C): «می‌شود»، «فیلدها»، «به‌روزرسانی»، «پیش‌نمایش»، «جست‌وجو».
- «ه» غیرملفوظ + «ی»: «پنجره‌ی» (با نیم‌فاصله و «ی»)، یکدست در کل محصول. هرگز «ۀ» یا «هٔ» ننویسید. پس از «ا» و «و»: «فضای ذخیره‌سازی»، «جست‌وجوی سریع».
- املای مرجع: تأیید، تأخیر، فرایند، مسئول، گفت‌وگو، جست‌وجو، به‌روزرسانی. فعل مرکب با «کردن» با فاصله‌ی کامل: «پاک کردن»، «فعال کردن».
- علامت‌ها: ویرگول «،»، نقطه‌ویرگول «؛»، علامت پرسش «؟»، گیومه « ». بدون فاصله پیش از علامت.
- اگر انگلیسی نقطه‌ی پایانی ندارد، فارسی هم ندارد؛ اگر دارد، فارسی هم دارد.
- اعداد داخل متن ترجمه با ارقام لاتین می‌آیند (`2,000` ← `2,000`)؛ تبدیل به ارقام فارسی در لایه‌ی نمایش انجام می‌شود.

## ۷. ترجمه‌نشدنی‌ها

- نام محصول‌ها و فناوری‌ها: NocoBase، PostgreSQL، JSON، SQL، API، iframe، OAuth، SMTP. در برچسب‌ها و متن رابط، URL و Markdown از واژه‌نامه پیروی می‌کنند («نشانی وب»، «مارک‌داون»)؛ فقط در نام کلید، کد و نمونه‌ها لاتین می‌مانند.
- مقادیر کد، کلیدهای پیکربندی، نام متغیرهای محیطی، مسیرها و نمونه‌های کد.
- نام NocoBase در رابط کاربری **حذف یا جایگزین نمی‌شود** ([ADR ۰۰۰۱](decisions/0001-nocobase-license.md) پس از ادغام).

## ۸. وقتی مطمئن نیستید

- اگر اصطلاح در واژه‌نامه نیست و بیش از یک بار تکرار می‌شود، پیشنهاد افزودنش به واژه‌نامه را در PR بنویسید.
- اگر معنای کلید بدون دیدن رابط کاربری روشن نیست، مسیر فایل و کلید را در توضیح PR فهرست کنید تا روی صفحه بررسی شود؛ حدس نزنید.
