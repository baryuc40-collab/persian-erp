# اتصال به Camunda / موتور BPMN

## اول: آیا لازم است؟

NocoBase خودش موتور گردش‌کار دارد (`plugin-workflow` و حدود ۲۰ نود: شرط، حلقه، موازی، تأخیر، درخواست HTTP، SQL، ایمیل، کار دستی و ...). برای بیشتر نیازهای ماژول‌های ERP همین کافی است و کاربران بدون‌کد هم راحت‌تر با آن کار می‌کنند.

Camunda وقتی ارزش دارد که:

- فرایند طولانی و چندمرحله‌ای بین چند سیستم است (نه فقط داخل NocoBase)
- استاندارد **BPMN 2.0 / DMN** برای سازمان یا ممیزی الزامی است
- نیاز به پایش، نسخه‌گذاری فرایند، تایمر و جبران خطا (compensation) در مقیاس بالا هست

**پیشنهاد:** تا پایان فاز ۵ با گردش‌کار خود NocoBase کار کنیم و اتصال BPMN را فاز ۶ قرار دهیم.

## دوم: کدام موتور؟ (تصمیم مجوز)

| گزینه | مجوز | نکته |
| --- | --- | --- |
| Camunda 8 (Zeebe) Self-Managed | از نسخه‌ی ۸.۶ برای **محیط عملیاتی مجوز پولی** لازم است؛ توسعه و آزمون رایگان | معماری ابری، gRPC/REST، Tasklist و Operate |
| Camunda 7 Community | پایان عمر نسخه‌ی رایگان | برای پروژه‌ی جدید توصیه نمی‌شود |
| **Operaton** (فورک جامعه‌محور Camunda 7) | Apache-2.0 | سازگار با API و BPMN نسخه‌ی Camunda 7، REST ساده |
| CIB seven (فورک Camunda 7) | متن‌باز با پشتیبانی تجاری | |

برای محصولی که قرار است در ایران و به‌صورت گسترده عرضه شود، خرید مجوز تجاری از شرکت‌های خارجی ممکن است به‌دلیل تحریم عملاً ناممکن باشد. پس **موتور متن‌باز (Operaton) گزینه‌ی امن‌تر پیش‌فرض است** و طراحی باید طوری باشد که بعداً Camunda 8 هم قابل جایگزینی باشد.

## سوم: معماری اتصال

یک پلاگین سمت سرور در NocoBase: `@persian-erp/plugin-bpm` با یک لایه‌ی انتزاعی `BpmEngine` و دو پیاده‌سازی (`OperatonAdapter`، `Camunda8Adapter`).

```
 کاربر NocoBase                             موتور BPMN
 ───────────────                            ──────────
 رکورد ایجاد شد ──(نود گردش‌کار «شروع فرایند»)──► start process instance
                                                   │
 صندوق کار فارسی ◄──(همگام‌سازی User Task)──────── user task
 (بلوک NocoBase) ──(تکمیل با فرم NocoBase)──────► complete task
                                                   │
 Collection ها ◄──(External Task Worker / Job Worker)── service task
                                                   │
 رویداد/گردش‌کار ◄──(پیام / webhook)──────────────── message / end event
```

چهار قطعه:

1. **نود گردش‌کار «شروع فرایند BPMN»** و «ارسال پیام»: تا کاربر بدون‌کد از گردش‌کار NocoBase فرایند Camunda را صدا بزند
2. **Worker** داخل پلاگین: کارهای سرویس (service/external task) را می‌گیرد و روی Collectionهای NocoBase با ACL همان سیستم اجرا می‌کند
3. **صندوق کار (Task Inbox)**: یک بلوک NocoBase که User Taskها را با فرم‌های ساخته‌شده در NocoBase نمایش می‌دهد؛ یعنی کاربر هیچ‌وقت به Tasklist انگلیسی Camunda نمی‌رود و همه‌چیز فارسی و جلالی می‌ماند
4. **نگاشت هویت**: کاربران و نقش‌های NocoBase به assignee/candidate group موتور

مدل‌سازی BPMN با Camunda Modeler / bpmn-js انجام می‌شود؛ در گام بعد می‌توان bpmn-js را با ترجمه‌ی فارسی داخل NocoBase جاسازی کرد.

## قدم‌های فاز ۶

1. (Opus) تصمیم نهایی موتور و طراحی `BpmEngine` + نمونه‌ی اثبات مفهوم با یک فرایند «درخواست خرید»
2. (Sonnet) پیاده‌سازی Worker و نود شروع فرایند
3. (Sonnet) بلوک صندوق کار و همگام‌سازی وضعیت
4. (Opus) بازبینی امنیت (ACL، احراز هویت بین دو سیستم) و پایداری (تکرار، خطا، تراکنش)
