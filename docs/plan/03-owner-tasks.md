# کارهایی که خود صاحب پروژه باید انجام دهد

هوش مصنوعی می‌تواند بیشتر کار را بنویسد، اما این موارد فقط از شما برمی‌آید.

## فوری (قبل از شروع فاز ۱)

1. **اتصال GitHub به Claude** از https://claude.ai/connect-github و نصب Claude GitHub App روی مخزن `persian-erp` تا عامل‌ها بتوانند شاخه و PR بسازند.
2. ~~**تصمیم مجوز NocoBase**~~ (انجام شد: صاحب پروژه بررسی کرد و مجوز برای هدف پروژه مشکلی ندارد؛ ثبت رسمی در STORY-001): بند ۵.۴ و ۷.۳ مجوز، ارائه‌ی عمومی SaaS/محصول بدون‌کد بر پایه‌ی NocoBase را منع می‌کند. یکی از این مسیرها را انتخاب کنید:
   - استفاده‌ی داخلی/پروژه‌ای برای مشتری‌های مشخص (با مجوز رایگان یا تجاری مناسب)
   - تماس با NocoBase برای مجوز تجاری/OEM یا همکاری (فارسی‌سازی خودش امتیاز مذاکره است)
   - مشورت با یک حقوق‌دان
3. **تأیید واژه‌نامه:** معادل فارسی ~۳۰۰ اصطلاح پایه را یک بار با دقت بازبینی کنید. همه‌ی ترجمه‌ها از آن پیروی می‌کنند.
4. **تأیید بک‌لاگ:** اپیک‌هایی که هوش مصنوعی می‌نویسد را بخوانید و تأیید یا اصلاح کنید.

## در طول کار

5. **بازبینی PRها:** حداقل PRهای واژه‌نامه، RTL و تقویم را خودتان روی صفحه ببینید.
6. **آزمون واقعی:** هر فاز را با داده‌ی واقعی یک کسب‌وکار امتحان کنید و ایرادها را به‌صورت استوری (با قالب [story.md](../../backlog/templates/story.md)) ثبت کنید.
7. **سرور:** یک سرور لینوکسی با Docker برای محیط آزمایشی (staging).
8. **حساب و بودجه‌ی Claude:** اشتراک Claude برای Claude Code و/یا کلید API برای ترجمه‌ی دسته‌ای.

## تصمیم‌های محصولی (قبل از فاز ۵)

9. فهرست و ترتیب ماژول‌های ERP و کاربران هدف (کسب‌وکار کوچک؟ سازمان؟)
10. مدل کسب‌وکار: اشتراکی، نصب روی سرور مشتری، یا متن‌باز با پشتیبانی پولی (به تصمیم مجوز وابسته است)
11. قوانین ایرانی که باید رعایت شود: سامانه‌ی مؤدیان، فاکتور رسمی، کدینگ حساب‌ها، استانداردهای حسابداری
12. انتخاب موتور BPMN برای فاز ۶ (Operaton متن‌باز یا Camunda 8 با مجوز پولی)

## مشارکت در جامعه

13. ثبت حساب در انجمن NocoBase و باز کردن یک issue درباره‌ی پشتیبانی فارسی/RTL تا تیم NocoBase از کار شما مطلع باشد و PRها پذیرفته شوند.
