# نوشتن اپیک و استوری با هوش مصنوعی

## ایده‌ی اصلی

شما **هدف** را می‌گویید، هوش مصنوعی **اپیک و استوری** می‌نویسد، شما **تأیید** می‌کنید، هوش مصنوعی **پیاده‌سازی** می‌کند، شما **بازبینی** می‌کنید. منبع حقیقت، فایل‌های داخل همین مخزن است تا هر عامل هوش مصنوعی بتواند آن‌ها را بخواند.

```
backlog/
  BACKLOG.md            فهرست اولویت‌دار اپیک‌ها و وضعیت آن‌ها
  templates/epic.md     قالب اپیک
  templates/story.md    قالب استوری
  epics/EPIC-001-<slug>/
    epic.md
    STORY-001-<slug>.md
    STORY-002-<slug>.md
```

اگر بخواهید روی برد GitHub هم ببینید، همین قالب‌ها به‌صورت Issue Template در `.github/ISSUE_TEMPLATE/` هست و عامل می‌تواند هر استوری تأییدشده را Issue کند. فایل‌ها منبع اصلی‌اند؛ Issue فقط برای پیگیری.

## چرخه‌ی کار

1. **هدف (شما):** یک پاراگراف. مثال: «می‌خواهم همه‌ی فیلدهای تاریخ جلالی باشند ولی در پایگاه داده میلادی ذخیره شوند.»
2. **اپیک (Opus):** با پرامپت «اپیک‌نویس» زیر، فایل `epic.md` ساخته می‌شود: مسئله، دامنه، خارج از دامنه، معیار پذیرش، ریسک، وابستگی.
3. **تأیید اپیک (شما):** وضعیت را از `draft` به `approved` تغییر دهید یا نظر بدهید.
4. **شکستن به استوری (Sonnet):** هر استوری باید در یک PR کوچک تمام شود، معیار پذیرش قابل‌آزمون (Given/When/Then) داشته باشد و فایل‌های درگیر را نام ببرد.
5. **پالایش (Opus، اختیاری):** بررسی اینکه استوری‌ها با هم کل اپیک را پوشش می‌دهند و همپوشانی ندارند.
6. **پیاده‌سازی (Sonnet):** «استوری STORY-00X را پیاده کن» ← شاخه + PR که در توضیحش به استوری لینک دارد.
7. **بازبینی (شما + Opus):** ادغام، و وضعیت استوری `done` می‌شود.

## پرامپت‌های آماده

### اپیک‌نویس

```
فایل‌های CLAUDE.md، docs/plan/01-roadmap.md و backlog/BACKLOG.md را بخوان.
هدف زیر را به یک اپیک با قالب backlog/templates/epic.md تبدیل کن
و در backlog/epics/EPIC-<شماره‌ی بعدی>-<slug>/epic.md ذخیره کن و
در BACKLOG.md ردیفش را با وضعیت draft اضافه کن.
اگر ابهامی هست، در بخش «پرسش‌های باز» بنویس؛ حدس نزن.
هدف: <هدف شما>
```

### استوری‌نویس

```
اپیک backlog/epics/EPIC-00X-.../epic.md تأیید شده است.
آن را به استوری‌هایی با قالب backlog/templates/story.md بشکن.
هر استوری: یک PR کوچک، معیار پذیرش Given/When/Then، فایل‌ها و پکیج‌های
درگیر NocoBase v2.2.22، و مدل پیشنهادی برای پیاده‌سازی.
کد را بررسی کن تا مسیر فایل‌ها واقعی باشد.
```

### پیاده‌ساز

```
استوری backlog/epics/EPIC-00X-.../STORY-00Y-....md را پیاده‌سازی کن.
فقط همان دامنه. آزمون بنویس. PR پیش‌نویس با لینک به استوری باز کن
و وضعیت استوری را in-review کن.
```

## قواعد کیفیت استوری

- یک استوری = یک خروجی قابل‌دیدن یا قابل‌آزمون
- معیار پذیرش بدون کلمات مبهم («مناسب»، «سریع»)
- اگر استوری بیش از یک پکیج NocoBase را عوض می‌کند، احتمالاً باید شکسته شود
- هر استوری RTL یا تاریخ باید تصویر قبل/بعد یا آزمون خودکار داشته باشد
