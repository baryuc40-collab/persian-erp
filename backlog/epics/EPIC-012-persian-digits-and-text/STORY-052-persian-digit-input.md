# STORY-052: پذیرش ارقام فارسی و عربی در ورودی‌ها

## روایت
به‌عنوان کاربر فارسی‌زبان، می‌خواهم بدون عوض کردن زبان صفحه‌کلید عدد وارد کنم.

## معیار پذیرش
- **Given** زبان فارسی **When** در فیلد عددی `۱۲۳٫۵` تایپ یا paste شود **Then** مقدار `123.5` ذخیره می‌شود
- **Given** فیلد متنی **When** `کد ۴۵` تایپ شود **Then** `کد 45` ذخیره می‌شود و با فونت FD همان `کد ۴۵` دیده می‌شود
- **Given** API یا ورود اکسل **When** رقم فارسی در فیلد عددی یا متنی بیاید **Then** سرور آن را به رقم لاتین تبدیل می‌کند

## یادداشت فنی
- کلاینت: یک شنونده‌ی سراسری `beforeinput` و `paste` روی `input` و `textarea` که `۰-۹`، `٠-٩` و `٫` را به `0-9` و `.` تبدیل می‌کند. ویرایشگر کد استثنا است.
- سرور: هم‌راه با STORY-053، یک hook روی `beforeSave` برای فیلدهای متنی و عددی.

## پیاده‌سازی
- `shared/latin-digits.ts`: تبدیل `۰-۹` و `٠-٩` به `0-9`؛ برای فیلد عددی `٫` به `.` و `٬` به `,` هم تبدیل می‌شود.
- کلاینت (`client/latin-digits-input.ts`): یک شنونده‌ی `input` در فاز capture روی `document`، فقط در زبان فارسی. مقدار را پیش از آن‌که React بخواند تبدیل می‌کند و چون هر نویسه یک نویسه می‌شود، جای مکان‌نما عوض نمی‌شود. در میانه‌ی ترکیب (IME) کاری نمی‌کند و در `compositionend` تبدیل می‌کند. این روش تایپ، paste و صفحه‌کلید موبایل را یک‌جا پوشش می‌دهد.
- سرور (`server/latin-digits.ts`):
  - رویداد سراسری `beforeValidate` برای فیلدهای `string`، `text`، `uid` و `sequence` و فیلدهای عددی، پس API و هر مسیر ذخیره‌ی دیگری هم پوشش داده می‌شود.
  - رابط‌های `number`، `integer` و `percent` در ورود اکسل پیش از تجزیه‌ی عدد، رقم را تبدیل می‌کنند.
  - رابط‌های تاریخ شمسی (STORY-043) هم تاریخ با ارقام فارسی (`۱۴۰۵/۰۷/۲۰`) را می‌خوانند.

## تصمیم‌ها
- فیلد رمز عبور، `input[type=email]`، `input[type=number]` و ویرایشگر کد (Monaco) تبدیل نمی‌شوند. رمز عبور عیناً هش می‌شود، تا رمزهای قدیمی که با رقم فارسی ساخته شده‌اند هنوز کار کنند.
- متن غنی و Markdown هم از نوع `text` هستند و تبدیل می‌شوند؛ نشانه‌گذاری HTML رقم فارسی ندارد، پس آسیبی نمی‌بیند. فیلدهای JSON دست نمی‌خورند.
